高可用架构设计旨在通过冗余、故障转移、负载均衡等手段，保证系统在硬件故障、网络异常情况下仍能提供服务。

核心指标：
- 可用性：99.9% = 全年宕机不超过 8.76 小时
- 99.99% = 不超过 52.6 分钟
- 99.999% = 不超过 5.26 分钟

高可用设计原则：
1. 冗余：关键组件多实例部署，避免单点故障
2. 故障转移：主节点故障自动切换到备用节点
3. 负载均衡：流量分发到多个节点，避免单点过载
4. 限流降级：保护系统不被流量压垮
5. 监控告警：及时发现问题，快速恢复
6. 灰度发布：降低发布风险，逐步放量

分层高可用方案：

1. 接入层：
   - DNS 轮询：多 IP 解析
   - CDN：内容分发，边缘节点冗余
   - SLB/Nginx：反向代理负载均衡，主备或集群部署

2. 应用层：
   - 多实例部署：无状态服务横向扩展
   - 健康检查：剔除故障节点
   - 自动扩缩容：根据负载动态调整实例数
   - 熔断降级：依赖服务故障时快速失败

3. 服务层：
   - 注册中心高可用：集群部署（Eureka 3 节点、Nacos 3 节点）
   - 服务多实例：每个服务至少 2 个实例
   - 跨可用区部署：机房级容灾

4. 数据层：
   - 主从复制：读写分离，主故障自动提升从
   - 分库分表：解决单库瓶颈
   - 多副本：数据多副本存储，防止单点数据丢失
   - 备份恢复：定期全量 + 增量备份

故障转移机制：
1. 心跳检测：定期检查节点健康状态
2. 选举机制：Raft、Paxos 选主
3. 自动切换：主故障，从自动提升为主
4. 客户端重连：自动连接新的主节点

容灾方案：
1. 同城双活：同城两个机房，实时同步
2. 异地多活：异地机房部署，数据异步复制
3. 两地三中心：同城两中心 + 异地一中心
4. 备份容灾：冷备、温备、热备

限流算法：
1. 计数器：固定窗口内计数
2. 滑动窗口：细化时间窗口
3. 令牌桶：恒定速率发放令牌
4. 漏桶：恒定速率处理请求

熔断降级：
- 熔断：错误率超阈值时直接拒绝请求，防止雪崩
- 降级：返回兜底数据或简化逻辑
- 隔离：线程池或信号量隔离，避免相互影响

监控体系：
- 指标监控：CPU、内存、QPS、响应时间
- 日志监控：异常日志告警
- 链路追踪：调用链路分析
- 业务监控：核心业务指标

信创高可用实践：基于麒麟OS + 达梦DB + 国产负载均衡设备，构建自主可控的高可用架构。
