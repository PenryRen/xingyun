Redis 是基于内存的高性能 Key-Value 数据库，常作为缓存中间件使用。

核心特性：
1. 内存存储：数据全部在内存中，读写速度极快（10万+ QPS）
2. 单线程模型：6.0 前命令执行单线程，避免上下文切换和锁竞争
3. 持久化：RDB 快照、AOF 日志两种方式
4. 数据结构：String、List、Hash、Set、ZSet、Bitmap、HyperLogLog、Geo

典型应用场景：
1. 缓存：热点数据缓存，减轻数据库压力
2. 分布式锁：SETNX + EXPIRE，或 Redisson 实现
3. 计数器：点赞数、浏览量、限流计数
4. 排行榜：ZSet 天然支持排序
5. 消息队列：List 的 LPUSH/BRPOP 实现简单队列
6. 会话存储：分布式 Session 共享

持久化策略：
- RDB：定期快照，恢复快，可能丢数据
- AOF：记录所有写命令，数据安全，文件大
- 混合持久化（4.0+）：RDB 全量 + AOF 增量

高可用方案：
1. 主从复制：一主多从，读写分离
2. 哨兵 Sentinel：监控主节点，自动故障转移
3. Cluster 集群：数据分片，16384 个槽位分布到多个节点

缓存常见问题：
1. 缓存穿透：查询不存在的 key，请求穿透到 DB
   解决：布隆过滤器、空值缓存
2. 缓存击穿：热点 key 过期瞬间大量请求打到 DB
   解决：互斥锁、热点 key 永不过期
3. 缓存雪崩：大量 key 同时过期
   解决：过期时间加随机值、多级缓存

数据淘汰策略：
- noeviction：内存满拒绝写入（默认）
- allkeys-lru：所有 key 中淘汰最久未用
- volatile-lru：设置了过期时间的 key 中淘汰
- allkeys-random：随机淘汰

国产化支持：Redis 是开源产品，可在麒麟OS上稳定运行，符合信创部署要求。
